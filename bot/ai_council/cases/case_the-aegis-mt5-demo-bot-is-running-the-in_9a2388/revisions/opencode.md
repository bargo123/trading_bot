Revised design: `outcome_log.jsonl` is partitioned once, by fire open-time, into a discovery window (where the two states and TP parameters are fixed) and an embargoed holdout starting at least two weeks after the last discovery fire, with a further untouched replication set kept sealed until the holdout result is registered; all replay stays offline and read-only. Operationally: "existing take-profit target logic" means the runner's shipped TP module at current parameters anchored to each fire's recorded entry price; "cost adjustment" means subtracting each fire's logged spread-plus-slippage from gross PnL before any statistic; "roughly unchanged trade count" means per-state holdout fire count within ±5% of discovery-period count, with partial fills and censored/still-open outcomes excluded from headline numbers but reported separately and a minimum 95% outcome-reconciliation rate required per state. Inference uses a day-blocked bootstrap (respecting within-day dependence among fires) with Holm correction across three pre-registered endpoints — holdout net expectancy > 0, payoff ratio > 0.5, trade-count stability — tested against a pre-registered minimum effect size of net expectancy ≥ +0.03/trade, not the full in-sample +0.1069. Regime drift is screened by comparing discovery versus holdout feature distributions (PSI < 0.25 per state), and any breach voids the run rather than being tuned away. If any gate fails, the challenger is recorded as rejected in `ExperimentRegistry` and `sealed_holdouts.jsonl` and never promoted; no code or champion changes occur outside the governed promote gates, demo-only throughout.
