**Proposal (rev 2):** Pre-register an ExperimentRegistry-tracked study that rebuilds `validated_states.v2` on a fixed weekly cadence from the reconciled-exit corpus (n=2,518), with feature set, gates, and selection rules version-frozen in the registry before the first rebuild; every rebuild emits a new immutable artifact version (`v2.YYYYMMDD`) rather than overwriting. Admissions are decided solely on data through a pre-registered cutoff T0, and the post-T0 demo stream is an untouched time-forward holdout evaluated exactly once per state at the end of a pre-specified 30-day window, with multiplicity controlled by Benjamini–Hochberg across all candidate states and fire-level autocorrelation handled by aggregating to one sample per (state, day). A state is admitted only if holdout expectancy exceeds 0 with a bootstrap 95% CI excluding zero across ≥100 non-overlapping fires net of the assumed 0.3-pip cost — replacing the weaker ≥50/≥0 criterion. "Materially negative" is defined ex ante as holdout expectancy < −0.3 pip/fire or equity drawdown exceeding the incumbent champion's historical p95; either triggers immediate quarantine — the state is excluded from the next artifact build, the prior artifact version remains pinned for all runtime reads until resolution, and the failure is sealed in `sealed_holdouts.jsonl` alongside the challenger record. To prevent repeated adaptation to the same stream, each state receives at most two pre-registered holdout evaluations ever; any further retest requires a new registry experiment on a holdout segment never previously inspected. Research-only throughout: no champion edit, no live YAML change, no order placement.
