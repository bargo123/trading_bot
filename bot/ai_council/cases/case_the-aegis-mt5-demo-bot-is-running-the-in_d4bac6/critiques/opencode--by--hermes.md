The proposal's headline claim is untested by its own criteria: "reduces false starts" is never operationally defined or measured — acceptance rests on MDD and expectancy proxies, so a pass would not establish the claimed mechanism; define false start (e.g., entry followed by invalidation within N bars) and test it directly alongside the financial metrics. The decision rule is post-hoc adjustable as written: "non-inferior" has no pre-registered margin or test statistic, and max drawdown is a single path-dependent point estimate that needs bootstrap or subperiod decomposition, not a raw holdout comparison — precisely the vagueness where holdout overfitting enters. Double-gating mechanically shrinks the trade sample, yet no minimum-N or power analysis backs the vague "statistically recorded trade counts," so underpowered non-inferiority could pass on noise, and there is no protection against iteratively re-testing variant definitions against the same sealed holdout. Safety-wise it's compliant (research-only, cost-net, no execution path), but "MT5 DEMO-equivalent" data must be pinned to actual recorded DEMO-feed quotes with the hypothesis and thresholds pre-registered in the ExperimentRegistry before first holdout touch, or the result is unauditable.
