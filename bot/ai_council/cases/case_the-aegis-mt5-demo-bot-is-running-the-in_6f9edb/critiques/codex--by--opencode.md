The one-hour window is a free hyperparameter with no stated provenance or sensitivity analysis (why not 30 or 90 minutes?), and reusing the same sealed holdout across successive challengers without a multiple-testing correction converts that holdout into a tuning set — classic selection overfitting. Key claims are unmeasurable as written: "high-impact news" has no calendar source, timezone, or event list, and "net expectancy improves" lacks any minimum effect size or significance threshold, so a +0.01 pip noise edge on ~100 trades would pass. Validation is missing entirely: no bootstrap/confidence intervals on expectancy deltas, no check that excluded news windows leave enough treated events to evaluate the change itself, and the invented acceptance gates may not match the governed criteria in `promote.py` — acceptance must go through those gates, not this ad-hoc triple. No live-trading violation is apparent (read-only, registered, challenger-only), but the demo-trade count criterion is meaningless unless tied to the actual sealed holdout records rather than an unspecified "eligible" pool.
